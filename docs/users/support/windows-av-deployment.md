# Windows 배포: 백신·폐쇄망 환경 성능 가이드

moli-code Windows SEA 실행 파일(`moli-code-vX.Y.Z-x64.exe`)을 백신(AV/EDR)이 상주하는
폐쇄망 PC에 배포할 때 시작 속도에 영향을 주는 요인과 대응 방법을 정리합니다.

## 왜 느려지는가

- **서명되지 않은 대용량 실행 파일**: SEA 실행 파일은 약 100MB의 단일 PE 파일입니다.
  코드 서명이 없으면 백신이 실행할 때마다 전체 파일을 딥 스캔할 수 있습니다.
  폐쇄망에서는 백신이 클라우드 평판 조회를 할 수 없어 스캔 결과 캐시가 약해지고,
  매 실행마다 재스캔되는 제품도 있습니다.
- **버전 업그레이드 = 새로운 해시**: 백신 콘솔에서 이전 버전 exe를 *해시 기준*으로
  화이트리스트했다면, 새 버전 배포 순간 화이트리스트가 무효화되어 다시 느려집니다.
- **최초 실행 시 에셋 추출**: 첫 실행 시 내장 에셋(ripgrep 등)을
  `%LOCALAPPDATA%\moli-code\sea-<hash>\`에 풀어놓습니다. 이때 exe(rg.exe) 쓰기가
  발생해 백신 행위 탐지가 개입할 수 있습니다. 이후 실행에서는 추출을 건너뜁니다.

## 권장 조치 (배포 관리자)

1. **코드 서명**: exe에 조직 코드서명 인증서로 서명하고, 백신 정책은 해시가 아닌
   *서명자(Publisher) 기준*으로 허용하세요. 버전 업그레이드 때마다 재등록할 필요가
   없어집니다.
2. **백신 예외 등록** (보안 정책이 허용하는 범위에서):
   - moli-code 실행 파일 설치 경로
   - `%LOCALAPPDATA%\moli-code\` (에셋 추출 디렉터리 — rg.exe가 여기서 실행됨)
3. **배포 파일 검증**: 배포 서버에 올린 exe가 최종 릴리스 빌드인지 SHA-256으로
   확인하세요. 같은 버전 번호로 여러 번 빌드된 경우 중간 빌드가 배포되면 성능
   문제가 재발할 수 있습니다.

## 대화형 모드가 느릴 때 (설정)

`@` 파일 자동완성은 워크스페이스 전체를 크롤링합니다. 백신이 모든 디렉터리 열람을
검사하는 환경에서는 아래 설정으로 스캔을 줄일 수 있습니다 (`settings.json`):

```json
{
  "context": {
    "fileFiltering": {
      "crawlCacheTtlSeconds": 1800,
      "enableRecursiveFileSearch": false
    }
  }
}
```

- `crawlCacheTtlSeconds` (기본 300): 크롤 결과 캐시 유지 시간. 길수록 재스캔이 줄어듭니다.
- `enableRecursiveFileSearch: false`: `@` 입력 시 전체 크롤 대신 디렉터리 단위
  탐색만 수행합니다. 매우 큰 워크스페이스에서 권장.
- 대상 프로젝트에 `.gitignore`/`.moliignore`가 없으면 빌드 산출물 폴더까지 전부
  크롤링됩니다. `.moliignore`에 대형 폴더(빌드 출력, 로그 등)를 등록하세요.

## 참고: 폐쇄망 관련 동작

- SEA 빌드는 npm 레지스트리 업데이트 확인을 하지 않습니다(v0.4.1+). 버전 확인은
  `molimate.config.json`의 `url`에 설정된 내부 서버(`/version.json`)로만 하며,
  3초 타임아웃 후 조용히 넘어갑니다.
- 내부 서버가 방화벽으로 차단된 세그먼트에서는 인증 다이얼로그의 원격 설정
  조회(5초 타임아웃)가 지연될 수 있습니다. 로컬 인증을 선택하면 원격 조회를
  건너뜁니다.
